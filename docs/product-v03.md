# FinPilot v0.3 · 从“研究数据”到“研究决策流程”

## 先用一句话理解

FinPilot 不是一个让大模型替你下单的聊天机器人。它是一个本地优先的投资研究辅助工作台：用户输入一个研究截止日，系统先在明确的数据和风险规则下筛选候选，再用确定性规则形成一个有现金余量的组合，最后用共同日期收益做压力诊断，并把“为什么入选、为什么被排除、数字怎么算、哪些假设不可靠”写成可复核的研究备忘录。

离线演示使用 8 个合成实体，名称是 `DEMO01`—`DEMO08`，不是现实证券。真实用户可以通过新的本地 CSV 入口导入自己的研究快照；导入材料标记为“用户提供、未独立核验”，不会被系统包装成已验证的行情或财报。

## 真实历史案例与估值敏感性

工作台现在包含一个“评测、真实案例与边界”页。它载入三组带来源的公共历史参考点：2020 疫情期间 S&P 500 的峰值/低点/恢复点，2022 收紧周期下 S&P 500 的几个收盘参考点，以及 2022 年美国10年期国债收益率的两个参考点。页面计算峰值到低点、低点到末点和起点到末点的描述性变化，并显示原始来源链接。

这些点位是稀疏的、版本化的公开参考快照，不是完整行情、实时数据或可交易回测。它们适合用来练习“如何定义冲击、如何解释恢复、如何把利率变化连接到久期”，而不是证明策略表现。完整研究仍需导入经过授权的日线数据。

投资研究页面还提供 EPS × 假设 PE 的估值敏感性表。它只回答“在不同假设倍数下，隐含价格如何变化”，不回答“合理目标价是多少”，不做概率预测，也不替代可比公司、DCF、盈利质量和治理分析。

环境要求 Python 3.10+。在仓库根目录执行：

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
python -m finpilot research --as-of 2025-12-31 --method equal
python -m finpilot export --output FinPilot演示工作台.html
python -m finpilot serve
```

然后打开 `http://127.0.0.1:8765`。第一次只看一个流程：

```text
选择研究截止日
  ↓
看股票池：哪些通过，哪些被排除，为什么
  ↓
看组合：每个候选的权重、现金和单票上限
  ↓
看压力：95%参数、共同日期历史回放、相关性压力
  ↓
导出研究证据和备忘录
```

如果只想使用静态文件：

```bash
python -m finpilot export --output /tmp/FinPilot演示工作台.html
open /tmp/FinPilot演示工作台.html
```

## 用户到底在解决什么问题

一个金融研究者通常不是缺一段“看起来专业”的文字，而是缺少一个可重复的工作顺序：先统一截止日，再把候选按可用数据和研究条件筛出来，然后明确组合规则，最后知道组合在哪些风险假设下会受损。FinPilot 把这条链路显式化。

它可以支持三类任务：

第一类是投资研究预筛。使用收入增长、经营利润率、自由现金流率、估值倍数、杠杆和价格风险做候选排序。结果是“值得继续研究的候选清单”，不是买入信号。

第二类是组合与风险解释。用户选择等权、得分权重或低波动倒数权重，设置单一持仓上限，系统会保留现金而不是为了凑满仓位违反上限。压力诊断使用共同日期的日收益，避免把不同标的的不同日期拼在一起。

第三类是面试和模型治理训练。用户可以查看每个数据字段、公式、来源标记和失败状态，解释为什么缺数据不能补 0、为什么报告期结束日不等于市场可见日、为什么压力损失不是 VaR 证明。

## 本地无 LLM 也能完成什么

本地确定性核心完成：CSV 解析和字段校验、点时过滤、财务筛选、PE/增长/利润率/杠杆条件、描述性评分、长仓组合、权重上限、现金保留、行业权重、HHI、共同日期收益、参数压力、相关性压力、历史回放、证据账本、JSON/Markdown 导出以及离线验收。

这些核心步骤不需要 API key，不向外发送用户数据，也不依赖大模型做金融算术。每个数字都可以从输入字段或明确公式重算。

## LLM 能做什么

LLM 是可选增强，不是系统依赖。通过 `python -m finpilot agent --question "..." --live-model`，用户可以显式接入自己的 OpenAI-compatible endpoint；endpoint、模型名和 key 只从环境变量读取。

LLM 适合做：把自然语言问题路由到“市场、基本面、信用、固收或组合”工具；把已经计算好的结果整理成研究提问清单；从已有 finding ID 中挑选与问题相关的项目；把证据和限制改写成更易读的摘要。

LLM 不允许做：直接计算 PE、Expected Loss、收益、权重或风险；发明 evidence ID；修改程序给出的数值；执行 shell、SQL 或任意网络请求；把合成数据说成真实证券；在点时检查失败时继续给出完整结论。

因此，面试时可以这样说：

> 我把 LLM 放在“问题理解和表达层”，把金融算术、数据门禁和风险控制留在确定性核心。这样即使没有 LLM，用户仍然能完成最重要的本地研究任务；接入 LLM 后，增加的是可读性、检索入口和追问效率，而不是不可审计的数字生成。

## 结果和当前边界

当前仓库已有单票研究、信用风险、固收敏感性、组合分配和共同日期压力诊断的代码路径；离线测试覆盖核心边界。合成演示不是现实市场验证，也不构成 alpha、投顾、授信或监管模型证明。

对真实数据的正确使用方式是：把经过授权的研究快照导入本地，保留数据来源和日期，先检查字段、单位、币种和点时口径，再让筛选运行。系统不会因为来源字段写了某个网站，就自动确认真实性。

生产化前仍需补充真实数据 provider、公司行为处理、财报修订政策、交易成本/流动性、组合回测、真实用户研究和模型质量评测。

## 技术栈与架构

项目使用 Python 3.10+、NumPy、pandas 和标准库 `unittest`。核心模块职责如下：

`data.py` 保存单标 fixture、Observation、Evidence、日期可见性和 hash；`pool.py` 生成多实体合成宇宙；`screen.py` 执行候选筛选和解释；`portfolio.py` 负责长仓权重、硬性 cap、现金和共同日期压力；`risk.py` 提供信用、固收和期权确定性计算；`backtest.py` 提供明确滞后执行的教育性回测；`runtime.py` 是受限 Agent 路径；`integrations.py` 是显式 opt-in 的 MCP/LLM 边界；`pipeline.py` 编排单票和研究切片；`workbench.html` 提供用户导向的可视化工作区。

> Screen a synthetic equity universe, build a capped long-only portfolio, stress it on common-date returns, and export an evidence-linked research memo — locally, reproducibly, without an LLM.

随后放一个 GIF 或截图，依次展示：候选表、排除原因、权重表、压力卡片和备忘录。再放 Quick Start、Data Contract、LLM boundary、Limitations。不要把“多 Agent”放在第一句，也不要用收益率截图作为主要卖点。
