# FinPilot 产品说明：证据优先的金融风险与研究工作台

## 1. 产品判断

FinPilot 不是“自动选股聊天机器人”，而是一个把金融数据、确定性计算、Agent 协作和人工复核串成证据链的研究工作台。它服务两个真实任务：让 AI 产品经理能够展示任务拆解、工具编排、评测、成本与安全边界；让金融岗位候选人能够用可复算算例展示点时数据、信用风险、固收敏感性、期权定价和回测纪律。

最小闭环是：固定研究对象和 as-of 日期，加载带来源与有效时间的观察值，执行市场/基本面/风险计算，做前视检查，生成研究备忘录和 trace。模型如果接入，只能解释已经验证的结果；它不能修改原始数值、替代日期判断、执行任意代码或绕过风险门禁。

## 2. 目标用户与场景

目标用户不是泛化的所有投资者，而是三类内部角色。研究员需要快速审阅财报型数据和市场信号；风险人员需要做 PD、LGD、EAD、Expected Loss、压力情景和集中度检查；产品/模型治理人员需要知道数据在哪里、公式是什么、模型输出是否被引用、什么情况下必须停止。

首个演示任务是：“在指定历史日期可获得的信息范围内，输出一份带证据的研究摘要，并展示一个有滞后执行、交易成本和基准对照的教育性回测。”第二个演示任务是：“在合成贷款组合上改变 PD 和 LGD，解释 EAD 加权预期损失、集中度和验证集指标变化。”

## 3. 产品原则

第一，数字先由确定性工具计算，叙述后生成。第二，报告期结束日不等于市场可用日，所有基本面数据必须带 filed_at/effective_at。第三，不知道就进入 review 或 blocked，不以 0、平均值或语言模型猜测填补。第四，回测结果是方法验证材料，不是 alpha 证明。第五，合成数据、外部服务、模型输出和真实研究结论分开标记。

## 4. 可验收功能

离线 fixture 模式不需要密钥或联网，固定种子生成合成市场、财报形态数据和 240 条合成贷款；同一输入可以产生相同 result_hash，但每次运行有独立 run_id。报告输出严格 JSON、Markdown memo、证据账本、Agent trace、point-in-time gate、回测参数、信用压力结果和固收/期权工具结果。

risk 子命令用于信用压力、模型验证指标、债券久期/凸性/DV01 和 Black–Scholes/Monte Carlo 检查；eval 子命令运行离线验收用例；serve 子命令只在本机提供只读 HTML、JSON 和 health 端点。live SEC、Yahoo 和外部 LLM 属于可插拔后续工作，连接前必须完成数据条款、密钥、工具白名单、限流和失败回退评估。

## 5. 产品指标与实验

当前仓库没有外部用户、留存、准确率或效率提升证据。上线前要做三类验证。任务完成率实验比较“原始数据+人工计算”和“FinPilot 带证据摘要”完成同一审阅任务的成功比例；引用覆盖实验检查关键 claim 是否绑定 evidence_id；错误门禁实验注入未来财报、未知单位、缺字段和异常模型输出，确认系统进入 review 而不是继续写报告。

事件建议为 `run_started`、`data_loaded`、`quality_gate_failed`、`calculation_completed`、`claim_created`、`human_review_requested`、`report_exported`。每条事件至少保存 run_id、mode、tool、status、latency_ms、error_code、data_source_kind；不要保存密钥和未经授权的原始文档。SQL 草案见能力映射文档，真正数据分析前必须定义事件表和权限。
